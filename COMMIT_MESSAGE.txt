Fix 0-products scrape: /shop/ isn't a real archive, hub regex too strict

You ran the scraper against the new default and got 0 products with
'the source layout may have changed' -- root cause was two separate bugs
in the default-source setup from the last two commits, not a layout
change on the site's side:

1. DEFAULT_SOURCE pointed --source-url directly at peptidessource.com's
   /shop/ page, but that page is a custom Elementor landing page with
   curated preview grids per category (Best Sellers, Cellular Growth &
   Signaling, ...), not a real paginated WooCommerce archive -- its
   markup doesn't match parse_catalog_page()'s card selectors at all, so
   it always finds 0 products regardless of pagination. The real,
   paginated per-category archives live at URLs like
   /product-category/research-peptides-by-type/<slug>/, confirmed to use
   standard WooCommerce archive markup (h2 titles, .price, /page/N/
   pagination) that the existing parser already handles correctly.

2. CATEGORY_HREF_RE only matched category paths with exactly one segment
   after the keyword (e.g. /product-category/research-peptide-vials/).
   peptidessource.com nests some categories two segments deep
   (/product-category/research-peptides-by-type/<slug>/), which the old
   regex silently dropped -- so even switching straight to
   --discover-category-hub against /shop/ would have missed most
   categories. Widened the regex to allow one or more nested segments
   between the keyword and the final slug.

Fix: DEFAULT_SOURCE -> None, DEFAULT_DISCOVER_HUB ->
https://www.peptidessource.com/shop/ (discover every real category link
off the landing page instead of scraping the landing page itself).
main()'s default-selection logic and the module docstring/help text are
updated to match; verified discover_category_links() against sample
hrefs modeled on the actual /shop/ page markup -- flat categories,
nested categories, a same-page anchor jump link, and a
filter-querystring variant of a nested category all resolve as
expected.
