Fix 403 from peptidessource.com: use browser-like User-Agent

The scraper's requests.Session self-identified as 'CatalogResearchBot/1.0
(+local catalog import; respects robots.txt)' with no other browser-like
headers, which peptidessource.com's WAF/bot-protection rejects outright
with a 403 -- unlike a 429/5xx this isn't transient, so get()'s
retry/backoff loop can't recover from it regardless of how long it waits.

build_session() now sends a standard desktop Chrome User-Agent plus the
Accept/Accept-Language headers a real browser sends. The two previous
default sources (corepeptides.com, limitlesslifenootropics.com) apparently
didn't enforce this as strictly, which is why the old bot UA worked
against them but not against peptidessource.com.

Flagging in case this doesn't fully resolve it: if peptidessource.com is
actually running a Cloudflare-style JS challenge (rather than a simple
UA/header rule), no amount of header-spoofing in plain requests will
get through, and we'd need a different approach (e.g. cloudscraper, or a
headless-browser-based fetch) -- let me know what the next run does.
